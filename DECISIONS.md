# EpiSurge — Decision Log

Every non-obvious choice in this project, with the evidence behind it.

**How to read this file.** Entries are chronological and never deleted — a
decision log is a record, not a status page. The **Status** column says
whether an entry still governs the code:

| Status | Meaning |
|---|---|
| **ACTIVE** | Governs the current implementation |
| **SUPERSEDED** | The reasoning was sound at the time; the figures or scope have since changed. The superseding entry is named. |
| **PENDING** | Decided but not yet implemented |

Numbers inside SUPERSEDED entries are preserved as they were measured. Do not
quote them as current — see the snapshot below.

## Standing rules

These govern all future work and should not be reversed without an experiment
that proves them wrong.

1. **Human hosts only.** The target is human ILI. Any genomic record with a
   named non-human host is excluded.
2. **As-of, not final.** Model inputs use values as published at the forecast
   origin. Only the target uses final revised values.
3. **Paired evaluation.** Every model comparison is scored on an identical row
   set per (fold, horizon, stratum), and the script verifies it.
4. **Per-fold reporting.** Pooled-across-fold figures are not reportable. A
   horizon whose sign flips across folds supports no claim.
5. **Phase stratification.** Because as-of genomic coverage is concentrated
   after the peak, every genomic result is reported stratified by `peak_side`
   or the horizon effect is confounded with seasonal phase.
6. **Flag flaws immediately**, however minor.
7. **Scope changes only when an experiment proves a current assumption wrong.**
   New ideas go to `FUTURE_WORK.md`.
